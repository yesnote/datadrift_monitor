# Common Active Learning Loop Phase 2 Log

## Implemented

- Added `configs/experiments/ppal_retinanet_voc.py` as a local ALOD experiment config ported from the PPAL VOC RetinaNet reference settings.
- Added dependency-light COCO-style pool helpers in `methods/common/`.
- Added deterministic `methods/random/` and detection-uncertainty-based `methods/entropy/` sampler modules with a shared `sample(...)` interface.
- Added `methods/ppal/adapter.py` with explicit PPAL step names and lazy local `mmdet.ppal` sampler construction hooks. It does not import or reference `code_refs`.
- Wired PPAL acquisition execution for `--execute --method ppal` through local `mmdet.ppal` DCUS and Diversity samplers. The imports remain lazy, so dry-runs do not load MMDetection/MMCV.
- Added `tools/run_active_learning.py`, a pathlib/subprocess-list based runner scaffold that:
  - accepts an experiment config path;
  - supports `--method {ppal,random,entropy}`;
  - defaults to `--dry-run` and only executes subprocess plans with `--execute`;
  - initializes `work_dirs/<experiment>/round_00/annotations/` from configured initial JSON files when they exist;
  - writes `active_learning_plan.json` under the configured `work_dirs/...` output directory;
  - rejects runtime config paths that are absolute, outside the repo root, or under `code_refs`.
- Kept the PPAL VOC experiment config under `data/...`, with train/inference image prefix set to standard `data/VOCdevkit/` for locally generated VOC0712 COCO JSON file names.
- Added an early guard so `--execute --method ppal` fails before launching expensive train/test commands until local DCUS/Diversity sampler execution is wired.

## Remaining Limitations

- No training, inference, or MMDetection import validation was run. This is intentional because `mmcv` imports hang in the current Codex shell environment.
- PPAL sampler execution is wired, but full execution was not run because it requires actual VOC pool JSONs, inference JSONs, `latest.pth`, and `image_dis.npy`.
- `random` and `entropy` lightweight acquisition can write next pool JSONs only when the configured oracle and current pool JSON files exist.
- PAL is not implemented in this phase.
